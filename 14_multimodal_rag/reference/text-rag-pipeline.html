The text RAG pipeline

One page. The five steps, the words that matter, and where each step lives in multimodal_rag.ipynb.

The five steps

① CHUNK

Cut documents into bite-sized pieces (index cards). One idea per card.

→

② EMBED

Each chunk → 1,536 numbers: its coordinates on the meaning map.

→

③ STORE

Coordinates + original text filed in Qdrant, the vector database.

→

④ RETRIEVE

Embed the question with the same model; grab the k nearest chunks.

→

⑤ ANSWER

Paste question + chunks into the prompt; the model answers and cites.

①–③ run once, up front (ingestion). ④–⑤ run on every question (query time).

Words that matter

RAG (Retrieval-Augmented Generation)
The open-book exam: look up the right snippets first, then answer only from them.
Embedding
A list of numbers acting as coordinates for meaning. Similar meaning → nearby coordinates.
Vector
Just another name for that list of numbers. “Vector” and “embedding” are used interchangeably.
Vector database (Qdrant)
A filing cabinet sorted by meaning: stores vectors + original text, finds nearest neighbors fast.
Chunk
One index card: a bite-sized piece of a document, the unit that gets embedded and retrieved.
k (as in k = 3)
How many nearest chunks retrieval brings back.
Grounding
Forcing the model to answer only from the provided context, with citations — no guessing.
Ingestion vs query time
Ingestion = the once-up-front work (①–③). Query time = the per-question work (④–⑤).

The one limitation to remember

Why this session exists Text embedding models are blind to images. A chart's numbers (ACME's “$27M”) live only in pixels, so this pipeline can never find or cite them. Fixing that is the whole point of multimodal RAG.
