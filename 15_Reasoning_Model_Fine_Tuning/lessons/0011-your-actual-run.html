You set report_to = "none", so there's no plotted reward-over-time chart saved anywhere — the only window into training is the text your own correctness_reward_func printed along the way. Two examples still visible near the very end of your log, right before training finished at step 175:

Wrong — bank interest

Computed compound interest wrong (got $2,519.42 instead of the gold $2,400 — treated 8% as compounding rather than simple interest paid out yearly), and the closing </answer> tag landed in the wrong place.

Even at the very last step, the model still gets some wrong — both on the math itself and occasionally on formatting. That's normal; 175 steps is described in your own notebook as enough to see reward turn upward, not enough for mastery (Unsloth recommends 300+ steps for stronger results).

A number that looks confusing: train_loss ≈ 0.0001 Your run's final summary shows train_loss: 0.00010429... — a number that low usually means "perfectly solved." Here it doesn't. GRPO's reported "loss" is a policy-gradient surrogate, not a normal prediction-error loss like Lesson 0006 warned about (Lesson 0006: "watch reward go up, not loss go down") — it commonly hovers near zero throughout training and isn't the number to trust for progress. The two real completions above are far more informative than that single number.

Before vs. after: the actual comparison

Same prompt, "Calculate pi," same frozen engine, only the attached adapter changes (Lesson 0006's "two personalities, one engine"):

Base model (no LoRA, no system prompt)

No tags at all. A rambling, multi-section answer listing four different methods (Monte Carlo, Leibniz, BBP, Chudnovsky) with Python code for each — reasonable content, zero structure.

Trained model (LoRA + system prompt)

Reliably produces <reasoning>/<answer> tags, exactly as trained — but the actual digits inside <answer> are garbled and wrong.
An honest read of this result This is actually a clean demonstration of exactly what got rewarded and what didn't. Format transferred perfectly — the model reliably uses the tags now, on a prompt it never saw in training. Correctness didn't, because it can't — GSM8K is whole-number word problems with one exact answer; "calculate pi" asks for an irrational number with infinite digits, a completely different kind of question the reward functions never covered. The training worked exactly as designed; this prompt was just never part of what it practiced.
