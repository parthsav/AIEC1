Lesson 0000 · Big Picture

Teaching a Model to Reason, Without Ever Showing It How

Every session so far has treated the model like a locked box: you send it a prompt, it sends back words. This session, for the first time, you open the box and change what's inside. This lesson is the 30,000-foot map of exactly what that means — read this one first.

Analogy first Imagine teaching someone to shoot free throws. One way: you physically move their arms through the "correct" motion, over and over, until they copy it. That's showing them how. The other way: you just let them shoot a hundred free throws, tell them which ones went in, and let them adjust on their own — you never touch their arms. That's rewarding them for results. This session uses the second way.

The first way has a name: supervised fine-tuning (SFT) — show the model worked examples of good reasoning, and it copies the pattern. The second way is reinforcement learning (RL) — score the model's own attempts, and let it discover what works. This notebook uses RL, specifically an algorithm called GRPO (Group Relative Policy Optimization) — the same core idea behind DeepSeek-R1.

Illustration — the GRPO loop

Watch the highlight travel around the loop. Every box glows once per lap — that's one training step. The model never sees a "correct" reasoning trace; it only ever sees a number telling it how well it did compared to its own other 7 attempts.

Two things make this cheap enough to run on one GPU

What full fine-tuning would cost

Llama-3.2-3B has 3 billion numbers. Updating all of them needs huge memory for gradients and optimizer state — far more than a normal GPU has.

What this notebook actually does

Freeze all 3 billion numbers. Attach a tiny trainable patch called LoRA next to a few key layers. Only the patch — a few million numbers — ever changes.

And instead of needing a second, separate "critic" network to judge how good each attempt was (the way classic RLHF/PPO does), GRPO judges each attempt against the average of its own group of 8. No critic network needed — that's the "group relative" part of the name, and a big reason this fits on a single consumer GPU.

Where this lives in your notebook 01_Reasoning_Fine_Tuning_Unsloth_GRPO.ipynb — the six-step loop above is described in the markdown cell right before Task 4 ("GRPO turns fine-tuning into a reward game"), and the actual training call is trainer.train() in Task 7.
